# P8: Hard limits on spend and time — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A ceiling on agent minutes, tokens or reported dollars per mission and per project per month; warn at the warning level, stop at 100% and ask whether to raise it.

**Architecture:**
- Domain: `entities/limits.ts` — metrics, `Limit`, `UsageTotals`, `evaluateLimit(s)`, `admits`, `worstLevel`, `limitFacts`, `monthWindow` (from a clock reading), incidents, the words (`reachedReason`, `warningNote`, `barLabel`, `heldLabel`, `suggestedRaise`), the backlog rule `pullAllowedAtSpend`, `normalizeLimits`, `withAmount`, `isLimitPause`. `Mission.limits`, `Workspace.defaultMissionLimits/monthlyLimits`; `usage` event `wallTimeMs`; `RAISE_LIMIT_OPTION`/`KEEP_PAUSED_OPTION` (affirmative: raise). `LimitRepositoryPort`.
- Persistence: migration 014; mission and workspace columns; `SqliteLimitRepository` (usage sums, incidents with a conditional `transition`).
- Runtimes: `wallTimeMs` through normalize, the generic CLI (`wallTimeMs`/`duration_ms`) and Claude Code (`duration_ms`).
- Application: `LimitService` (admit, refusal, afterUsage, stop, decide, validateDecision, setMissionLimits, limitsChanged, heldFor, missionView, alerts, usage). The executor records wall time for every run, calls `afterUsage` after `recordUsage` and `admit` before leases; the scheduler calls `admit` before the first agent dispatch per mission per pass; `ApprovalService` validates and applies limit decisions in its transaction; `MissionService.resume` refuses at a limit; `BacklogService.#pullFor` filters held candidates; projections carry limits and alerts.
- Daemon: mission PATCH `limits`, workspace PATCH `defaultMissionLimits`/`monthlyLimits` (then `limitsChanged`), `GET /v1/workspaces/:id/usage`, `raiseTo` on decide.
- Desktop: `LimitFields`, Metrics → Limit, `LimitDecision` on limit cards, mission-page limit panel, Home banners, Repositories → Limits, backlog held subtitle, New mission limit.

**Tech stack:** TypeScript (ESM), better-sqlite3, zod, React 18 + React Query, raw CDP for acceptance.

**Spec:** `docs/superpowers/specs/2026-09-26-p8-limits-design.md` (binding, including Rulings).

## Self-review

- The hard stop is enforced at admission (scheduler and executor) and after usage; the stubbed scheduler proves no dispatch in an over-limit mission even when ticked directly, and the daemon run proves a lowered limit stops the work with no run going ahead.
- The month comes from `clock.epochMs()`; the check asserts neither the service nor the domain reads the system clock.
- Deciding twice: the approval's PENDING check answers the second with 409, and the incident's conditional `open → resolved` makes the rule itself run once; the check fires both decisions concurrently and counts one resume.
- "Not reported" stays null end to end (sums, views, facts absent, bars "not reported").
- Copy states numbers: "Limit reached: 15 of 12 agent minutes", "15 / 30 agent min", "Raise it above 15 agent minutes".
