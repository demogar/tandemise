# P6: Ready before planning — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A rough request is refined into accepted criteria and answered questions, and the daemon refuses to plan a DRAFT mission until it is ready.

**Architecture:**
- Domain: `entities/refinement.ts` — question entity, limits, `READY_TO_PLAN_GATE`, `readinessFacts`, `evaluateReadiness` (gate outcome + the Plan button sentence). Ports: criteria repository grows `listProposed/propose/decide/get/listDecided`; new `MissionQuestionRepositoryPort`.
- Persistence: migration 012 (artifacts CHECK widened in place, 006 pattern; criteria status columns; `mission_questions`), repositories.
- Artifacts: `Refinement` and `StatusReport` schemas, templates, budgets; the Refinement template carries the product-owner guidance.
- Evaluation: `ready.*` in `GATE_FACT_VOCABULARY`.
- Application: `ReadinessService` (counts → gate) used by `PlanningService#enterPlanning`, `MissionService.create` (planNow) and the views; `RefinementService` (the bounded pass, verdicts, answers, hand-added criteria, view); planner prompt and context compiler read accepted criteria and answers; projection inbox gains `refinements`.
- Daemon: five routes. Desktop: "Get it ready" panel, gated Plan button, NewMission "Create and refine …", Inbox row.

**Spec:** `docs/superpowers/specs/2026-09-26-p6-ready-design.md` (binding, including Rulings).

## Global Constraints

- `npm run ci` green; boundaries and design tokens included.
- One migration (012). Released migrations untouched; P5's 011 untouched too.
- No new approval kinds. Readiness is a gate expression over counts; the agent's output never decides it.
- Renderer uses `import type` only; existing classes and tokens only.
