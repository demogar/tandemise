# P15 plan: setup as code, and gates that can pass

> For agentic workers: REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps are checkboxes; tick them as they land.

**Goal:** export and import the project's setup as files in `.tandemise/`, and reject every gate that could never pass when it is written.

**Architecture:**
- The fact vocabulary moves to `@tandemise/domain` with a `scope` per fact; `@tandemise/evaluation` re-exports it.
- One pure validator (`lintGate`) in domain, called from workflow parse/compile, plan validation, materialize and import.
- `git.clean` is measured by `CheckService` as a check result; `security.required_checks` and `checks.<name>` are removed.
- Setup codec (render, read, diff) is pure in `@tandemise/application/setup`; `SetupService` gathers rows and applies choices in one transaction; the daemon's `FileSetupFolder` does the disk and git work.

**Tech stack:** TypeScript, zod, `yaml` (now also a dependency of `@tandemise/application`), better-sqlite3, React.

**Spec:** `docs/superpowers/specs/2026-09-26-p15-setup-design.md`.

## Rulings made while planning

- `git.clean` is stored as a check result so it follows the "newest result wins" rule and shows with the checks, rather than a transient measurement passed into `#assess` from five call sites.
- The codec lives in application (it needs `yaml`), not domain; domain stays dependency-free except zod.
