# P3b Evals: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every run of a gated step is scored with measured facts; a finished step can be saved as an eval case; and a suite of cases runs against a candidate setup (models, skills or a setup folder) in hidden trial missions, producing a side-by-side scorecard before anything goes live.

**Architecture:**
- Migration 020 adds `run_scores`, `eval_suites`, `eval_cases`, `eval_runs`, `eval_trials` and `missions.eval_trial_id`. Ids live in `@tandemise/shared`, entities and ports in `@tandemise/domain`, SQLite repositories in `@tandemise/persistence`, the pure scorecard in `@tandemise/evaluation`.
- The executor writes a `run_scores` row after every gate assessment (both `#assess` call sites), using a new `GateService.assess` that returns the full fact map.
- A trial is a hidden mission (`evalTrialId` set) that the `EvalRunner` drives by calling `TaskExecutor.execute` directly. One SQL condition in the mission list hides trials from every list reader; a handful of in-memory reads get an explicit check. One sync executor seam, `trialContext`, supplies the frozen role, knowledge, decisions and answers for a trial.
- Eval case inputs are copied into a content-addressed eval blob store (`<home>/evals/blobs/<sha256>`), because the artifact store is keyed by id, not hash.
- Every check is a `scratch/*.mjs` node script against `dist/`, registered in `scripts/run-checks.mjs` `OFFLINE_CHECKS`; real-app proof is a CDP suite in `scratch/acceptance/p3-evals/`.

**Tech Stack:** Node 22, TypeScript ESM, zod, SQLite (`node:sqlite` via `@tandemise/persistence`), Electron + React, `electron-vite`.

**Spec:** `docs/superpowers/specs/2026-09-16-p3-outside-contributions-design.md`, **Part B** (lines 313–574), sections B1–B7 and Rulings 8–11. Read it first. This plan supersedes the "P3b — evals" section (Tasks 9–17) of `docs/superpowers/plans/2026-09-16-p3-outside-contributions.md`, which was drafted before P3a merged and got several names, lines and seams wrong (listed under *Corrections to the earlier draft* at the end).

## Review Focus

1. **Daemon restart mid-run.** Recovery (`engine/recovery.ts:99-106,115-124`) must not requeue a trial task; on boot the runner marks a `running` eval run `failed` with `The daemon stopped during this run.`, its running trial `cancelled`, the trial task `CANCELLED`, and removes the trial worktree and branch. Pinned in Task 13.
2. **A runtime that reports no cost.** Trials still run, costs read as unknown (never `$0`), the run shows `This runtime doesn't report cost, so your cap can't stop this run.` and the cap is not claimed to have held. Pinned in Task 13.
3. **A case whose role was deleted, or whose input blob is gone,** is refused at `startRun`, naming the case (`role_missing` / `input_missing`), instead of failing every trial. Pinned in Task 13.
4. **The runtime is busy with real work** (`execute` returns `deferred`). The runner waits and retries, and a trial is not marked failed for waiting; after 10 minutes of deferral it ends `blocked` with the deferral reason. Pinned in Task 13.
5. **Deleting a suite (or a case) while a run on it is running** is refused 409 with `already_running`; deleting the source mission of a case leaves the case intact and runnable. Pinned in Tasks 12 and 13.

- "Attempts" are counted per **(taskId, round)** group of scores, ordered by `scoredAt`: the first row is attempt 1. This avoids `Run.attempt`, which is a run number that feedback passes also advance.
- `summarizeRunScores`: group by `roleId` × `model`. `runs` = row count. `firstAttemptPassRate` = groups whose first row passed ÷ groups (null when no groups). `meanAttemptsToPass` = mean index+1 of the first passing row, over groups that have one (null when none). `criteriaFailed` = sum of `criteria.failed` over rows (null criteria count 0). Rates divide by `completed` (null when 0). `gatePassRate` = completed with `score.gatePassed`. `firstAttemptPassRate` = completed with `score.firstAttemptPassed`. `criteria` = sums over completed trials with non-null criteria, null if none. `meanAttempts` over completed. `overBudget` = sum. **Spend and the cap.** After each trial: `spent` = sum of `run.usage.costUsd` over runs of all this run's trial missions (`runs.listByMission`), `costUnmeasured` = any finished run with `usage === null` or `costUsd == null`. If `spent >= spendCapUsd` → remaining queued trials `cancelled`, run `stopped_at_cap` with reason `Stopped at your $<cap> cap`. A run whose cost is unmeasured cannot be stopped by the cap; `getRun` reports `costUnmeasured: true` and the UI shows the copy from Global Constraints.

**Cancel.** `cancelRun`: run must be `queued`/`running` → else `not_running` "This run has already finished."; mark remaining queued trials `cancelled`, `runner.cancel(runId)` aborts the live trial (its trial ends `cancelled`, cleaned up), run `cancelled`, scorecard over finished trials.

**End.** `scorecard = scoreEvalRun(trials.map(...), repeats)` for every end state (completed, stopped, cancelled, failed), `finishedAt`, status.

**`contextFor(mission)`**: `mission.evalTrialId` → trial → run → `variants[trial.variant].roles[step.roleId].role` plus the case snapshot's `knowledge`, `decisions`, `answers`. Keep a small in-memory cache keyed by trial id for the live trial (it's called on every `execute` and prompt compile); fall back to the repositories. Return `null` if anything is missing (the executor then blocks the trial, Task 4).

**`recoverInterrupted()`**: for each `running` run: its `running` trial → task `CANCELLED` (tasks repository, `statusReason: 'The daemon stopped during this run.'`), clean up as in step 8, trial `cancelled`; other queued trials `cancelled`; run `failed` with reason `The daemon stopped during this run.`, scorecard over finished trials. `queued` runs stay queued (they never started).

## Rulings made while planning

1. **Case inputs live in a separate content-addressed eval blob store** (`<home>/evals/blobs`), because the artifact store is keyed by id and markdown bodies are not hash-addressed. A case therefore survives its mission and any store cleanup.
2. **One sync executor seam, `trialContext(mission)`,** supplies the trial's frozen role, knowledge, decisions and answers. Knowledge is workspace-level, so without it a trial would read today's knowledge, not the case's.
3. **`ask_human` in a trial answers "nobody" and the agent continues.** Parking a worker mid-run for a question nobody can answer would only hit the deferral timeout. The spec's "would-be card ends the trial blocked" still holds for cards the executor itself creates (missing skill).
4. **A tool approval in a trial is denied**, for the same reason.
5. **Trial tasks are written with `NO_APPROVAL`, no staffing, and `onExhausted: 'fail'`,** so review, sign-off and intervention cards are never reached; the executor also guards each site.
6. **Only a gated step can be a case**; the gate is the score.
7. **Attempts are counted per (task, round) in score order,** not from `Run.attempt`, which feedback passes also advance.
8. **Trial missions stay `DRAFT` while running** (never dispatchable) and are hidden by the same list SQL that hides the P10 report holder.
9. **An unknown cost is unknown, never $0**, both in the scorecard and in spend; the cap cannot stop a run whose cost is unmeasured, and the UI says so.
10. **"Try on evals" on the Skills screen works after the update is imported**, because updating imports the new version but roles keep their pins until changed; the candidate moves those roles to `latest`.
11. **The runner is a lifecycle component next to the scheduler**, and boot recovery runs after `RECOVERY_SERVICE` and before `lifecycle.start()`.
